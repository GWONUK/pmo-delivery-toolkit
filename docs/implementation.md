# 구현 설명

## 배포 상태 처리

`python/delivery_adapter.py`는 승인과 전송 함수를 외부에서 받아 동작하는 라이브러리입니다. 이 파일만 실행해서 서버에 접속하는 CLI는 없습니다.

입력한 구성과 승인 조건을 검사한 뒤 변경 의도를 기록하고, 응답과 준비 상태를 확인합니다. 결과가 불명확한 요청은 자동으로 반복하지 않습니다. 복구 역시 별도의 승인과 이전 구성에 묶인 작업으로 취급합니다. 동일 인스턴스의 재실행을 막지만, 프로세스 사이의 중복 실행 방지와 영구 잠금은 호출자가 제공해야 합니다.

기본 대상은 거래 API와 탐지 엔진에 필요한 Service, Deployment, Route입니다. 원본에 있는 추가 화면 프로필도 명시적 입력 검사와 함께 보존했습니다. 현재 모의시험은 두 업무 애플리케이션을 기준으로 하며, 추가 화면 프로필과 `local_time_checks` 및 `initial_lease`의 별도 조합은 이번 시험 묶음에서 검증하지 않았습니다.

이 코어의 준비 상태 판정은 전체 서비스 인수 판정이 아닙니다. 토큰 검증, 실제 TLS 통신, 데이터베이스 연결과 업무 기능 검증은 별도로 필요합니다. 테스트에 쓰는 승인 함수와 전송 함수는 합성 자료 전용입니다.

## 구성 파일 수집과 해시 대조

`python/producer_snapshot.py`는 전체 40자리 Git 커밋을 받아 고정된 소스 경로 9개를 수집합니다. 수정 중인 작업 폴더나 미추적 파일은 읽지 않고, 누락된 Git 객체를 네트워크에서 자동으로 가져오지도 않습니다. Git 객체 ID를 재계산하고 파일별 SHA-256을 기록합니다.

`producer_bridge.py`에는 이 수집기가 쓰는 Git 읽기 경계와, 별도로 검토된 렌더 검사기를 연결하는 코드가 있습니다. 검사기 연결은 정확한 해시로 고정된 소스만 실행합니다. 이 저장소에는 실제 검사기나 운영용 구성 파일이 없으며, 시험에서는 합성 검사기를 사용합니다.

수집 결과의 해시 일치는 바이트가 같다는 뜻입니다. 코드의 안전성, 배포 승인 또는 구성 파일에 비밀이 없음을 보장하지 않습니다. 허용된 파일에 민감한 내용이 들어 있으면 수집물에도 포함되므로, 수집 결과는 공개 전에 별도 검토해야 합니다.

## Ansible 설정과 점검

원본의 CentOS Stream 10 조건을 유지했습니다. `site.yml`은 공통 패키지, 시간 동기화와 Kubernetes 사전 조건을 설정하고, `precheck.yml`은 현재 상태를 읽어서 확인합니다. `roles/k8s_prereq/tasks/verify.yml`은 실제 상태 검사와 설정 작업의 dry run을 구분합니다.

다만 원본의 swap 판정은 그대로 보존했습니다. swap이 켜진 서버에서 설정 플레이북을 `--check`로 실행하면, 실제로 swap을 끄지 않은 상태에서 후속 검사에 실패할 수 있습니다. dry run 통과를 전체 적용 가능성으로 해석해서는 안 됩니다.

`harden_svc_ansible_key.yml`은 관리 대상 SSH 키가 정확히 하나 있는지 검사한 뒤 제한 조건을 적용합니다. 공개본의 키 문자열과 주소는 합성 자료입니다. 합성 시험에서는 원본 플레이북의 읽기 전용 검사 태스크 두 개만 추출해 임시 파일을 대상으로 실행하며, 실제 authorized_keys를 변경하지 않습니다.

공개용 플레이북은 `toolkit_allow_remote_execution`이 명시적으로 참일 때만 원격 작업을 진행합니다. 기본 예시에서는 거짓입니다. 이 값만 바꾼다고 적용 준비가 끝나는 것은 아닙니다. 실제 대상의 인벤토리, 서비스 계정, 경로, 관리망과 복구 절차를 검토한 뒤 별도로 승인해야 합니다.

허용 조건은 사전 태스크와 역할 및 작업 블록에 적용했습니다. 이것은 실수로 실행하는 일을 줄이기 위한 장치이며 접근통제 시스템은 아닙니다. 플레이북이나 변수를 수정할 권한이 있는 실행자는 조건을 바꿀 수 있습니다. SSH 키 예시의 제한 주소는 설정 문자열과 두 검사 정규식, 합성 자료에 함께 들어 있으므로 변경 시 모두 일치시켜야 합니다.

## 원격 적용 전 확인할 사항

- 대상 서버와 OS, 네트워크 경로가 승인된 환경인지 확인합니다.
- SSH 호스트 키 검증을 유지하고 필요한 최소 권한만 부여합니다.
- 설정 변경 전 복구 가능한 원본과 복구 절차를 준비합니다.
- 사전 점검, 변경, 변경 후 점검을 각각 기록합니다.
- 예상과 다른 상태가 나오면 자동으로 계속 진행하지 않고 원인을 확인합니다.

이번 공개 작업에서는 이 원격 적용 절차를 실행하지 않았습니다.
